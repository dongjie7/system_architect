## 一、进程的基本概念

### 1.1 进程的定义

**进程（Process）** 是程序在数据集合上的一次执行过程，是系统进行**资源分配和调度**的基本单位。

**进程与程序的区别：**

| 对比项 | 程序 | 进程 |
|--------|------|------|
| 性质 | 静态指令集合 | 动态执行过程 |
| 生命周期 | 永久（文件形式） | 暂时（创建→消亡） |
| 并发性 | 无 | 有 |
| 资源占有 | 无 | 拥有资源 |
| 对应关系 | 一对多 | 一个程序可对应多个进程 |

### 1.2 进程的描述——进程控制块（PCB）

**PCB（Process Control Block）** 是进程存在的唯一标志，OS通过PCB感知进程的存在。

```c
// PCB 核心结构（简化版）
struct pcb {
    int pid;              // 进程标识符
    int state;            // 进程状态
    int priority;         // 优先级
    struct context {      // CPU上下文（现场信息）
        int pc;           // 程序计数器
        int registers[N]; // 通用寄存器
        int psw;          // 程序状态字
    } context;
    struct mem_info {     // 内存信息
        int *page_table;  // 页表指针
        int code_seg;     // 代码段
        int data_seg;     // 数据段
    } mem;
    int fd_table[N];      // 打开文件描述符表
    int parent_pid;       // 父进程ID
    int exit_code;        // 退出码
};
```

**PCB包含的信息：**
1. 进程标识信息（PID）
2. 处理机状态信息（寄存器、PC、PSW）
3. 进程调度信息（状态、优先级）
4. 进程控制信息（资源清单、打开文件）

## 二、进程的状态与转换

### 2.1 三状态模型

```
         创建
          │
          ▼
      ┌───────┐
      │ 就绪  │←──────────┐
      │Ready  │           │
      └───┬───┘           │
          │ 被调度        │ 时间片到/
          ▼               │ 被抢占
      ┌───────┐           │
      │ 运行  │───────────┘
      │Running│
      └───┬───┘
          │ I/O请求/
          │ 等待事件
          ▼
      ┌───────┐
      │ 阻塞  │
      │Blocked│
      └───┬───┘
          │ I/O完成/
          │ 事件发生
          └──────────→ 就绪队列
          
          运行结束 → 终止态
```

### 2.2 五状态模型（考试标准）

```
创建态 → 就绪态 → 运行态 → 终止态
              ↑        │
              │        │
              └── 阻塞态 ──┘
```

**状态转换规则（必考）：**

| 转换 | 触发条件 | 方向 |
|------|----------|------|
| 就绪→运行 | 被调度程序选中，分配CPU | 必然发生 |
| 运行→就绪 | 时间片用完 / 被更高优先级抢占 | 必然发生 |
| 运行→阻塞 | 主动请求I/O、等待某事件 | 主动行为 |
| 阻塞→就绪 | I/O完成、等待事件发生 | 被动行为 |

> **考试陷阱**：
> - 阻塞→运行：**不可能直接转换**！必须先经过就绪态
> - 就绪→阻塞：**不可能**！只有运行态才能变为阻塞态
> - 运行→阻塞是**主动**的（进程自己请求）
> - 阻塞→就绪是**被动**的（外部条件满足）

### 2.3 状态转换的代码实现

```c
// 进程状态枚举
typedef enum {
    PROCESS_NEW,      // 创建态
    PROCESS_READY,    // 就绪态
    PROCESS_RUNNING,  // 运行态
    PROCESS_BLOCKED,  // 阻塞态
    PROCESS_EXITED    // 终止态
} ProcessState;

// 状态转换核心逻辑
void schedule() {
    // 从就绪队列选择进程
    Process *next = pick_from_ready_queue();
    if (next) {
        current_process->state = PROCESS_READY;  // 当前→就绪
        save_context(current_process);            // 保存上下文
        current_process = next;
        next->state = PROCESS_RUNNING;            // 选中→运行
        restore_context(next);                    // 恢复上下文
    }
}

void block_process(Process *p, Event event) {
    p->state = PROCESS_BLOCKED;     // 运行→阻塞
    p->wait_event = event;          // 记录等待事件
    add_to_wait_queue(p, event);    // 加入等待队列
    schedule();                     // 重新调度
}

void wakeup_process(Process *p) {
    remove_from_wait_queue(p);      // 从等待队列移除
    p->state = PROCESS_READY;       // 阻塞→就绪
    add_to_ready_queue(p);          // 加入就绪队列
}
```

## 三、进程控制

### 3.1 进程创建

```c
// Unix/Linux 进程创建
pid_t pid = fork();     // 创建子进程（复制父进程）
if (pid == 0) {
    // 子进程
    exec("new_program"); // 加载新程序
} else {
    // 父进程
    waitpid(pid, &status, 0); // 等待子进程结束
}
```

**fork() 的关键特性：**
- 子进程是父进程的**完整副本**
- 子进程获得**新的PID**
- 采用**写时复制（COW, Copy-On-Write）**优化
- fork()在父进程中返回子进程PID，在子进程中返回0

### 3.2 进程终止

```c
// 进程终止方式
exit(0);           // 正常退出（自愿终止）
abort();           // 异常退出（信号SIGABRT）
kill(pid, SIGKILL);// 强制终止其他进程
```

**终止原因：**
- 正常结束（exit）
- 出错退出（错误/异常）
- 被其他进程杀死（kill）
- 超时终止

### 3.3 进程挂起与激活

```
就绪态 ←→ 就绪挂起态
阻塞态 ←→ 阻塞挂起态

挂起原因：
1. 内存紧张，将进程换出到外存
2. 用户/OS主动挂起调试
3. 等待外部事件
```

## 四、线程（高频考点）

### 4.1 线程的概念

**线程（Thread）** 是CPU调度的基本单位，是进程内的一个执行单元。

**进程 vs 线程：**

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 资源分配 | 拥有独立资源 | 共享所属进程资源 |
| CPU调度 | 是调度单位（传统） | 是调度单位（现代） |
| 内存空间 | 独立地址空间 | 共享进程地址空间 |
| 开销 | 创建/切换开销大 | 创建/切换开销小 |
| 通信 | 需要IPC机制 | 直接读写共享内存 |
| 安全性 | 互不影响 | 一线程崩溃可能影响全进程 |

### 4.2 线程的实现方式

#### 4.2.1 用户级线程（ULT）

```
┌─────────────────────────────┐
│  进程                       │
│  ┌──────┬──────┬──────┐    │
│  │线程1 │线程2 │线程3 │    │  ← 用户空间管理
│  └──────┴──────┴──────┘    │
│  ┌─────────────────────┐   │
│  │ 线程库（运行时系统） │   │  ← 用户级调度
│  └─────────────────────┘   │
├─────────────────────────────┤
│         内核                 │  ← 只看到一个"进程"
└─────────────────────────────┘
```

- 线程管理在**用户空间**完成
- 内核不知道线程存在
- 优点：创建/切换快，无需内核支持
- 缺点：一个线程阻塞，整个进程阻塞；无法利用多核

#### 4.2.2 内核级线程（KLT）

```
┌─────────────────────────────┐
│  进程                       │
│  ┌──────┬──────┬──────┐    │
│  │线程1 │线程2 │线程3 │    │
│  └──────┴──────┴──────┘    │
├─────────────────────────────┤
│         内核                 │  ← 管理每个线程
│  ┌──────┬──────┬──────┐    │
│  │KLT1  │KLT2  │KLT3  │    │
│  └──────┴──────┴──────┘    │
└─────────────────────────────┘
```

- 线程管理由**内核**完成
- 优点：一个线程阻塞不影响其他线程；可利用多核并行
- 缺点：创建/切换开销大，需内核支持

#### 4.2.3 多对多模型（混合）

```
多个用户级线程 映射到 多个内核级线程
→ 结合两者优点
→ 如 Solaris 的线程实现
```

### 4.3 线程实现代码示例

```c
// POSIX 线程（pthreads）示例
#include <pthread.h>
#include <stdio.h>

void *thread_func(void *arg) {
    int id = *(int *)arg;
    printf("线程 %d 正在运行\n", id);
    return NULL;
}

int main() {
    pthread_t threads[3];
    int ids[3] = {1, 2, 3};
    
    // 创建线程
    for (int i = 0; i < 3; i++) {
        pthread_create(&threads[i], NULL, thread_func, &ids[i]);
    }
    
    // 等待线程结束
    for (int i = 0; i < 3; i++) {
        pthread_join(threads[i], NULL);
    }
    
    printf("所有线程已完成\n");
    return 0;
}
```

## 五、进程调度算法（核心考点）

### 5.1 调度层次

```
高级调度（作业调度）  → 决定哪些作业调入内存
     ↓
中级调度（对换调度）  → 决定哪些进程换出到外存
     ↓
低级调度（进程调度）  → 决定哪个就绪进程获得CPU
```

### 5.2 调度算法对比（必考计算）

| 算法 | 思想 | 特点 | 适用场景 |
|------|------|------|----------|
| **FCFS** | 先来先服务 | 简单公平；对短作业不利 | 批处理 |
| **SJF/SPF** | 短作业优先 | 平均等待时间最短；可能饥饿 | 批处理 |
| **SRTF** | 最短剩余时间优先 | SJF的抢占版本 | 交互式 |
| **RR** | 时间片轮转 | 公平；时间片选择关键 | 分时系统 |
| **优先级** | 按优先级调度 | 可能饥饿；可结合老化 | 实时/通用 |
| **多级反馈** | 多级队列+时间片+反馈 | 综合最优 | 通用OS |

### 5.3 调度算法详解与计算

#### FCFS（先来先服务）

```
进程  到达时间  服务时间
P1    0        8
P2    1        4
P3    2        2

执行顺序: P1 → P2 → P3
P1: 等待0, 完成8
P2: 等待7, 完成12
P3: 等待10, 完成14

平均等待时间 = (0 + 7 + 10) / 3 = 5.67
平均周转时间 = (8 + 11 + 12) / 3 = 10.33
```

#### SJF（短作业优先）

```
进程  到达时间  服务时间
P1    0        8
P2    1        4
P3    2        2

P1先到达，先执行（0-8）
P1完成后，P2和P3都已到达，选短的P3（8-10），再P2（10-14）

平均等待时间 = (0 + 10 + 6) / 3 = 5.33
平均周转时间 = (8 + 13 + 8) / 3 = 9.67
```

#### RR（时间片轮转）

```
进程  服务时间  时间片=2
P1    6        P1(0-2) → P2(2-4) → P3(4-6) → P1(6-8) → P2(8-10) → P1(10-12)
P2    4
P3    2

P1完成时间=12, 等待=12-6=6
P2完成时间=10, 等待=10-4=6
P3完成时间=6,  等待=6-2=4

平均等待时间 = (6+6+4)/3 = 5.33
```

#### 优先级调度

```
进程  服务时间  优先级（大=高）
P1    10       3
P2    1        1
P3    2        4
P4    1        2

按优先级: P3(4) → P1(3) → P4(2) → P2(1)

P3: 0-2, 等待0
P1: 2-12, 等待2
P4: 12-13, 等待12
P2: 13-14, 等待13

平均等待时间 = (0+2+12+13)/4 = 6.75
```

#### 多级反馈队列调度

```
队列1: 时间片=1, 优先级最高
队列2: 时间片=2, 优先级中
队列3: 时间片=4, 优先级低（FCFS）

规则:
1. 新进程进入队列1
2. 时间片用完未结束 → 降到低优先级队列
3. 低优先级队列空闲 → 高优先级可抢占
4. 在低队列完成的进程不需要降级

示例:
P1(服务时间=8): Q1(0-1) → Q2(1-3) → Q3(3-11)
P2(服务时间=3): Q1(1-2) → Q2(2-4)
P3(服务时间=1): Q1(2-3) 完成!
```

### 5.4 调度性能指标

```
周转时间 = 完成时间 - 到达时间
等待时间 = 周转时间 - 服务时间 = 等待CPU的时间
响应时间 = 首次上CPU时间 - 到达时间（分时系统）

带权周转时间 = 周转时间 / 服务时间

平均周转时间 = Σ周转时间 / n
平均等待时间 = Σ等待时间 / n
平均带权周转时间 = Σ带权周转时间 / n
```

### 5.5 调度算法代码实现

```c
// 进程调度核心数据结构
typedef struct {
    int pid;
    int arrival_time;    // 到达时间
    int burst_time;      // 服务时间
    int priority;        // 优先级
    int remaining_time;  // 剩余时间（用于抢占式）
    int start_time;      // 开始执行时间
    int finish_time;     // 完成时间
    int waiting_time;    // 等待时间
    int turnaround_time; // 周转时间
} Process;

// FCFS 调度算法
void fcfs_schedule(Process processes[], int n) {
    int current_time = 0;
    
    for (int i = 0; i < n; i++) {
        // 等待进程到达
        if (current_time < processes[i].arrival_time) {
            current_time = processes[i].arrival_time;
        }
        
        processes[i].start_time = current_time;
        processes[i].finish_time = current_time + processes[i].burst_time;
        processes[i].turnaround_time = processes[i].finish_time - processes[i].arrival_time;
        processes[i].waiting_time = processes[i].turnaround_time - processes[i].burst_time;
        
        current_time = processes[i].finish_time;
    }
}

// 时间片轮转调度
void rr_schedule(Process processes[], int n, int quantum) {
    // 使用队列实现
    Queue ready_queue;
    init_queue(&ready_queue);
    
    int current_time = 0;
    int completed = 0;
    
    // 初始将所有进程加入队列
    for (int i = 0; i < n; i++) {
        if (processes[i].arrival_time <= current_time) {
            enqueue(&ready_queue, i);
        }
    }
    
    while (completed < n) {
        int idx = dequeue(&ready_queue);
        
        if (processes[idx].remaining_time <= quantum) {
            // 进程在当前时间片内完成
            current_time += processes[idx].remaining_time;
            processes[idx].remaining_time = 0;
            processes[idx].finish_time = current_time;
            completed++;
        } else {
            // 时间片用完，重新入队
            current_time += quantum;
            processes[idx].remaining_time -= quantum;
            enqueue(&ready_queue, idx);
        }
        
        // 检查新到达的进程
        for (int i = 0; i < n; i++) {
            if (processes[i].arrival_time <= current_time && 
                processes[i].remaining_time > 0 &&
                !in_queue(&ready_queue, i) && i != idx) {
                enqueue(&ready_queue, i);
            }
        }
    }
}
```

## 六、上下文切换

### 6.1 上下文切换过程

```
进程A运行中
  → 发生中断/时间片到
  → 保存A的上下文到PCB（PC、寄存器、SP等）
  → 更新A的状态为就绪
  → 从就绪队列选择进程B
  → 更新B的状态为运行
  → 从B的PCB恢复上下文
  → 执行进程B
```

### 6.2 上下文切换开销

```
上下文切换时间 = 
  保存旧进程上下文 + 加载新进程上下文 + 调度决策时间

典型开销:
  用户级线程切换: ~微秒级
  内核级线程切换: 几微秒
  进程切换: 几十微秒（需切换地址空间、刷新TLB）
```

### 典型真题

**【选择题】以下关于进程和线程的叙述中，正确的是（ ）**
A. 线程是资源分配的基本单位
B. 进程的PCB是进程存在的唯一标志
C. 同一进程内的线程不能共享进程的资源
D. 用户级线程的切换需要内核支持

**答案：B**（时间片大到每个进程都能一次完成，等价于FCFS）
