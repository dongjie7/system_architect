## 一、操作系统基本概念

### 1.1 什么是操作系统

操作系统（Operating System, OS）是管理计算机**硬件与软件资源**的系统软件，是用户和计算机硬件之间的接口层。

**核心定义要素：**
- 操作系统是**系统软件**（非应用软件）
- 操作系统是**资源管理者**（CPU、内存、I/O、文件）
- 操作系统是**用户与硬件的接口**

### 1.2 操作系统的四大特征（必考）

| 特征 | 含义 | 关键点 |
|------|------|--------|
| **并发** | 多个事件在同一时间段内发生 | 区别于并行（同一时刻）；并发是宏观同时、微观交替 |
| **共享** | 系统资源可供多个并发进程共同使用 | 互斥共享（打印机）、共享访问（磁盘） |
| **虚拟** | 将物理实体变为逻辑上的对应物 | 虚拟处理器、虚拟内存、虚拟设备 |
| **异步** | 进程以不可预知的速度向前推进 | 执行结果可再现性（相同初始条件→相同结果） |

> **考试陷阱**：并发 ≠ 并行
> - 并发（Concurrency）：宏观上同时，微观上交替执行（单CPU即可）
> - 并行（Parallelism）：微观上也是同时（需要多CPU/多核）

### 1.3 操作系统的发展与分类

**按分类：**

| 类型 | 特点 | 典型代表 |
|------|------|----------|
| 批处理操作系统 | 成批处理作业，无交互能力 | IBM OS/360 |
| 分时操作系统 | 多用户分时使用，交互式 | UNIX |
| 实时操作系统 | 及时响应，高可靠性 | VxWorks、μC/OS |
| 网络操作系统 | 管理网络资源 | Windows Server |
| 分布式操作系统 | 多台计算机协同，用户透明 | Amoeba |
| 嵌入式操作系统 | 资源受限、实时性强 | Android、FreeRTOS |
| 微内核操作系统 | 最小化内核，服务在用户态运行 | MINIX、seL4 |

**操作系统发展里程碑：**
```
手工操作 → 批处理 → 多道批处理 → 分时 → 实时 → 网络/分布式 → 嵌入式/移动
```

## 二、操作系统的内核结构

### 2.1 内核的两种架构（高频考点）

#### 2.1.1 宏内核（Monolithic Kernel）

```
┌─────────────────────────────────┐
│         用户应用程序             │
├─────────────────────────────────┤
│         系统调用接口             │
├─────────────────────────────────┤
│  ┌──────┬──────┬──────┬──────┐  │
│  │进程  │内存  │文件  │设备  │  │
│  │管理  │管理  │系统  │驱动  │  │
│  └──────┴──────┴──────┴──────┘  │
│         硬件抽象层               │
├─────────────────────────────────┤
│           硬件                   │
└─────────────────────────────────┘
```

- 所有服务运行在**内核态**（特权态）
- 优点：效率高，组件间通信快
- 缺点：模块耦合度高，一个模块崩溃整个系统崩溃
- 典型代表：**Linux**、传统UNIX

#### 2.1.2 微内核（Microkernel）

```
┌─────────────────────────────────┐
│         用户应用程序             │
├─────────────────────────────────┤
│         系统调用接口             │
├──────┬──────┬──────┬────────────┤
│进程  │内存  │文件  │设备驱动    │  ← 用户态服务
│服务  │服务  │服务  │服务        │
├──────┴──────┴──────┴────────────┤
│      微内核（IPC + 基础调度）    │  ← 内核态
├─────────────────────────────────┤
│           硬件                   │
└─────────────────────────────────┘
```

- 仅保留最核心功能在**内核态**（进程通信、基本调度）
- 其他服务作为**用户态进程**运行
- 优点：可靠性高、可扩展性好、安全性强
- 缺点：进程间通信（IPC）开销大，性能较低
- 典型代表：**MINIX 3**、seL4、QNX、Windows NT（混合）

#### 2.1.3 对比总结

| 对比项 | 宏内核 | 微内核 |
|--------|--------|--------|
| 运行态 | 大部分在内核态 | 大部分在用户态 |
| 性能 | 高 | 较低（IPC开销） |
| 可靠性 | 低（一损俱损） | 高（服务隔离） |
| 可扩展性 | 差 | 好 |
| 安全性 | 较低 | 高 |
| 代表 | Linux、UNIX | MINIX、seL4 |

### 2.2 操作模式的切换

**用户态 vs 内核态：**

```
用户态（User Mode）
  ├── 只能执行非特权指令
  ├── 访问受限
  └── 应用程序运行在此

内核态（Kernel Mode / 特权态 / 管态）
  ├── 可执行所有指令（包括特权指令）
  ├── 可访问所有资源
  └── OS内核运行在此

模式切换触发条件：
  1. 系统调用（trap / 陷入）     → 用户态 → 内核态
  2. 中断（interrupt）            → 用户态 → 内核态
  3. 异常/故障（exception/fault） → 用户态 → 内核态
```

> **考试重点**：
> - **陷入（Trap）**：有意为之，如系统调用 `read()`、`write()`
> - **中断（Interrupt）**：外部硬件信号，如键盘输入、定时器
> - **异常（Exception）**：CPU执行指令时检测到错误，如除零、缺页

## 三、中断机制（核心考点）

### 3.1 中断的分类

```
中断
├── 外中断（硬件中断）
│   ├── 可屏蔽中断（Maskable Interrupt）  ← INTR引脚，可通过CLI/STI控制
│   └── 非屏蔽中断（NMI）                 ← 必须处理，如电源故障
└── 内中断（软件中断）
    ├── 陷入（Trap / 系统调用）            ← INT指令，有意触发
    ├── 故障（Fault）                      ← 可恢复，如缺页异常
    └── 终止（Abort）                      ← 不可恢复，如硬件错误
```

### 3.2 中断处理过程

```
1. 中断请求 → 外设发出中断信号
2. 中断判优 → 多个中断同时请求时，按优先级处理
3. 中断响应 → CPU保存当前状态（PC、寄存器等）
4. 中断 servicing → 执行中断处理程序（ISR）
5. 中断返回 → 恢复现场，继续执行被中断的程序
```

**关键细节：**
- 中断向量表：存储中断处理程序入口地址
- 中断优先级：NMI > 硬件故障 > 定时器 > I/O设备
- 中断嵌套：高优先级中断可以打断低优先级中断处理

### 3.3 系统调用（System Call）

系统调用是用户程序请求OS服务的**唯一入口**。

**分类：**
| 类别 | 示例 |
|------|------|
| 进程控制 | fork(), exit(), wait() |
| 文件操作 | open(), read(), write(), close() |
| 设备管理 | ioctl(), read(), write() |
| 信息维护 | getpid(), time(), date() |
| 通信 | pipe(), shmget(), msgget() |

**系统调用过程：**
```
用户程序 → 系统调用（如 read()）
  → 参数压栈/寄存器
  → 执行 trap 指令（如 INT 0x80 或 syscall）
  → CPU切换到内核态
  → 查中断向量表，跳转到系统调用处理程序
  → 执行实际服务
  → 返回结果
  → CPU切换回用户态
  → 继续执行用户程序
```

## 四、操作系统的运行环境

### 4.1 特权指令与非特权指令

| 类型 | 说明 | 举例 |
|------|------|------|
| **特权指令** | 只能在**内核态**执行 | 设置定时器、开关中断、修改页表基址寄存器、I/O指令 |
| **非特权指令** | 用户态和内核态都可执行 | 算术运算、逻辑运算、地址翻译 |

> **考试高频判断题**：
> - "清内存"指令 → 特权指令 ✓
> - "开/关中断" → 特权指令 ✓
> - "设置定时器" → 特权指令 ✓
> - "算术加法" → 非特权指令 ✓

### 4.2 操作系统的启动过程

```
加电 → ROM中的BIOS/UEFI自检（POST）
  → 加载引导扇区（Boot Sector）
  → 加载引导程序（Bootloader，如GRUB）
  → 加载OS内核到内存
  → 初始化内核数据结构
  → 启动第一个进程（init/systemd，PID=1）
  → 系统进入就绪状态
```

## 五、操作系统提供的接口

### 5.1 两类接口

```
操作系统接口
├── 命令接口
│   ├── 联机命令接口（交互式）  → Shell命令（CLI）
│   └── 脱机命令接口（批处理）  → JCL作业控制语言
├── 程序接口
│   └── 系统调用（API）         → 唯一能获取OS服务的途径
└── 图形用户接口（GUI）
```

### 5.2 Shell 基础

Shell是命令解释器，属于**用户态程序**（不是内核的一部分）。

```bash
# 常见Shell类型
/bin/sh      # Bourne Shell
/bin/bash    # Bourne Again Shell（Linux默认）
/bin/zsh     # Z Shell（macOS默认）
```

## 六、本章高频考点速记

### 必背知识点

1. OS的四大特征：**并发、共享、虚拟、异步**（并发是最基本特征）
2. 并发与并行的区别：并发=宏观同时微观交替；并行=微观也同时
3. 内核态与用户态的切换：系统调用、中断、异常触发
4. 宏内核 vs 微内核：性能 vs 可靠性/安全性
5. 特权指令只能在内核态执行；系统调用是用户获取OS服务的唯一入口
6. 中断处理优先级：NMI > 可屏蔽中断
7. 操作系统启动：BIOS → Bootloader → 内核 → init进程

### 典型真题

**【选择题】以下关于操作系统特征的叙述中，正确的是（ ）**
A. 并发性是指多个程序在同一时刻执行
B. 虚拟是指将物理资源变为逻辑上的对应物
C. 异步性是指程序的执行结果不可再现
D. 共享是指系统中的资源可被所有用户任意使用

**答案：B**
- A错：并发是同一时间段，不是同一时刻（那是并行）
- C错：异步是指以不可预知速度推进，但执行结果可再现
- D错：共享分为互斥共享和同时共享，不是任意使用

**【选择题】在操作系统中，（ ）只能在管态（内核态）下执行。**
A. 算术运算指令  B. 数据传送指令  C. 开中断指令  D. 条件转移指令

**答案：C**
- 开/关中断属于特权指令，只能在管态执行
