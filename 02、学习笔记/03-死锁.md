## 一、死锁的基本概念

### 1.1 什么是死锁

**死锁（Deadlock）**：多个进程因竞争资源而造成的一种僵局，各进程都在等待其他进程释放资源，但无人愿意主动释放。

```
死锁示例：
进程P1：持有资源R1，请求资源R2
进程P2：持有资源R2，请求资源R1

结果：P1等待P2释放R2，P2等待P1释放R1 → 死锁

    P1 ──持有──→ R1
    ↑              │
    │              ↓
   请求          等待
    │              ↑
    ↓              │
    P2 ──持有──→ R2
```

### 1.2 死锁的四个必要条件（必考）

| 条件 | 含义 | 能否破坏 |
|------|------|----------|
| **互斥条件** | 资源一次只能被一个进程使用 | 不能破坏（某些资源本质互斥） |
| **请求与保持** | 进程持有资源的同时请求新资源 | 可以破坏（一次性申请所有资源） |
| **不可剥夺** | 进程已获得的资源不能被强制剥夺 | 可以破坏（允许抢占） |
| **循环等待** | 存在进程-资源的循环等待链 | 可以破坏（按序申请资源） |

> **考试重点**：四个条件必须**同时满足**才会发生死锁。破坏其中任意一个即可预防死锁。

### 1.3 资源分配图

```
资源分配图（Resource Allocation Graph）：
- 进程节点：圆圈 P1, P2, ...
- 资源节点：方框 R1(3), R2(2)  ← 括号内为资源总数
- 请求边：Pi → Rj（进程请求资源）
- 分配边：Rj → Pi（资源分配给进程）

死锁判断：
- 无环 → 一定不死锁
- 有环 + 每类资源只有1个实例 → 一定死锁
- 有环 + 每类资源有多个实例 → 可能死锁（需进一步分析）
```

## 二、死锁处理策略

### 2.1 四种处理策略

| 策略 | 思想 | 实现难度 | 资源利用率 |
|------|------|----------|------------|
| **鸵鸟算法** | 忽略死锁 | 最简单 | 高 |
| **死锁预防** | 破坏四个必要条件之一 | 容易 | 较低 |
| **死锁避免** | 动态检查是否安全 | 中等 | 中等 |
| **死锁检测+恢复** | 允许死锁，检测后恢复 | 较难 | 高 |

## 三、死锁预防

### 3.1 破坏请求与保持条件

**方法**：进程在开始执行前一次性申请所有资源

```c
// 破坏请求与保持
void process() {
    // 一次性申请所有需要的资源
    acquire_all(resource1, resource2, resource3);
    
    // 使用资源
    use(resource1);
    use(resource2);
    use(resource3);
    
    // 一次性释放
    release_all(resource1, resource2, resource3);
}
```

**缺点**：
- 资源利用率低（某些资源只在后期使用）
- 可能导致饥饿（一直等待所有资源）
- 难以预知进程需要哪些资源

### 3.2 破坏不可剥夺条件

**方法**：允许进程在无法获得所有请求资源时，主动释放已持有的资源

```c
// 破坏不可剥夺
void process() {
    acquire(resource1);
    
    if (!try_acquire(resource2)) {
        // 无法获得resource2，释放已获得的resource1
        release(resource1);
        wait();
        // 重新申请
        acquire(resource1);
        acquire(resource2);
    }
}
```

**缺点**：
- 实现复杂
- 可能导致饥饿
- 反复申请释放增加开销

### 3.3 破坏循环等待条件

**方法**：对所有资源编号，进程只能按序号递增的顺序申请资源

```c
// 破坏循环等待
// 资源编号: R1=1, R2=2, R3=3

void process() {
    // 必须按编号从小到大申请
    acquire(R1);      // 先申请R1
    acquire(R2);      // 再申请R2
    acquire(R3);      // 最后申请R3
    
    // 使用资源
    use_all();
    
    // 释放（顺序无所谓）
    release(R3);
    release(R2);
    release(R1);
}
```

**优点**：简单有效
**缺点**：
- 实际使用的资源可能不是连续的
- 新资源加入需要重新编号

## 四、死锁避免——银行家算法（核心考点）

### 4.1 安全状态

**安全状态**：系统能够按某种顺序为每个进程分配资源并使其完成。

**安全序列**：如果存在一个进程序列 <P1, P2, ..., Pn>，使得每个进程Pi所需的资源都能被当前可用资源加上之前所有进程释放的资源所满足，则系统是安全的。

### 4.2 银行家算法数据结构

```c
// 数据结构
int Available[MAX_RESOURCES];    // 各资源当前可用数量
int Max[MAX_PROCESSES][MAX_RESOURCES];     // 各进程最大需求
int Allocation[MAX_PROCESSES][MAX_RESOURCES]; // 各进程已分配资源
int Need[MAX_PROCESSES][MAX_RESOURCES];    // 各进程还需要的资源

// 关系公式
Need[i][j] = Max[i][j] - Allocation[i][j]
Available[j] = Total[j] - Σ Allocation[i][j]
```

### 4.3 银行家算法流程

```
进程Pi请求资源Request[i]：

1. 检查请求是否合法
   if Request[i] > Need[i] → 错误，请求超过最大需求

2. 检查是否有足够资源
   if Request[i] > Available → 等待，资源不足

3. 试探性分配
   Available = Available - Request[i]
   Allocation[i] = Allocation[i] + Request[i]
   Need[i] = Need[i] - Request[i]

4. 执行安全性算法
   if 安全 → 确认分配
   else → 恢复原状态，进程等待
```

### 4.4 安全性算法

```c
// 安全性检查算法
bool is_safe() {
    int Work[MAX_RESOURCES] = Available;  // 工作向量
    bool Finish[MAX_PROCESSES] = {false}; // 完成标记
    int safe_sequence[MAX_PROCESSES];     // 安全序列
    int count = 0;
    
    while (true) {
        bool found = false;
        
        // 找一个可以完成的进程
        for (int i = 0; i < n; i++) {
            if (!Finish[i] && Need[i] <= Work) {
                // 进程i可以完成
                Finish[i] = true;
                safe_sequence[count++] = i;
                
                // 释放进程i持有的资源
                for (int j = 0; j < m; j++) {
                    Work[j] += Allocation[i][j];
                }
                found = true;
            }
        }
        
        if (!found) break;  // 没有可完成的进程
    }
    
    // 所有进程都能完成则安全
    return count == n;
}
```

### 4.5 银行家算法实例（必会计算）

**题目**：
系统有3类资源（A=10, B=5, C=7），T0时刻5个进程状态如下：

| 进程 | Max(A,B,C) | Allocation(A,B,C) | Need(A,B,C) |
|------|------------|-------------------|-------------|
| P0   | 7,5,3      | 0,1,0             | 7,4,3       |
| P1   | 3,2,2      | 2,0,0             | 1,2,2       |
| P2   | 9,0,2      | 3,0,2             | 6,0,0       |
| P3   | 2,2,2      | 2,1,1             | 0,1,1       |
| P4   | 4,3,3      | 0,0,2             | 4,3,1       |

**解答**：

```
1. 计算Available
   Available = Total - ΣAllocation
   A: 10 - (0+2+3+2+0) = 3
   B: 5 - (1+0+0+1+0) = 3
   C: 7 - (0+0+2+1+2) = 2
   Available = (3, 3, 2)

2. 安全性检查
   Work = (3, 3, 2)
   
   第1轮：
   - P0: Need(7,4,3) > Work(3,3,2) ✗
   - P1: Need(1,2,2) ≤ Work(3,3,2) ✓ → 执行完，Work = (3,3,2)+(2,0,0) = (5,3,2)
   - P2: Need(6,0,0) > Work(5,3,2) ✗
   - P3: Need(0,1,1) ≤ Work(5,3,2) ✓ → 执行完，Work = (5,3,2)+(2,1,1) = (7,4,3)
   - P4: Need(4,3,1) ≤ Work(7,4,3) ✓ → 执行完，Work = (7,4,3)+(0,0,2) = (7,4,5)
   
   第2轮：
   - P0: Need(7,4,3) ≤ Work(7,4,5) ✓ → 执行完，Work = (7,4,5)+(0,1,0) = (7,5,5)
   - P2: Need(6,0,0) ≤ Work(7,5,5) ✓ → 执行完，Work = (7,5,5)+(3,0,2) = (10,5,7)
   
   安全序列：<P1, P3, P4, P0, P2>
   结论：系统处于安全状态

3. P1请求(1,0,2)
   - Request(1,0,2) ≤ Need(1,2,2) ✓
   - Request(1,0,2) ≤ Available(3,3,2) ✓
   - 试探分配：
     Available = (3,3,2)-(1,0,2) = (2,3,0)
     Allocation[1] = (2,0,0)+(1,0,2) = (3,0,2)
     Need[1] = (1,2,2)-(1,0,2) = (0,2,0)
   
   - 安全性检查：
     Work = (2,3,0)
     P0: Need(7,4,3) > Work ✗
     P1: Need(0,2,0) ≤ Work ✓ → Work = (2,3,0)+(3,0,2) = (5,3,2)
     P2: Need(6,0,0) > Work ✗
     P3: Need(0,1,1) ≤ Work ✓ → Work = (5,3,2)+(2,1,1) = (7,4,3)
     P4: Need(4,3,1) ≤ Work ✓ → Work = (7,4,3)+(0,0,2) = (7,4,5)
     P0: Need(7,4,3) ≤ Work ✓ → Work = (7,4,5)+(0,1,0) = (7,5,5)
     P2: Need(6,0,0) ≤ Work ✓ → Work = (7,5,5)+(3,0,2) = (10,5,7)
     
     安全序列：<P1, P3, P4, P0, P2>
     结论：可以分配！

4. P4请求(3,3,0)
   - Request(3,3,0) ≤ Need(4,3,1) ✓
   - Request(3,3,0) > Available(2,3,0) ✗（A资源不足）
   - 结论：P4必须等待
```

### 4.6 银行家算法代码实现

```c
// 银行家算法完整实现
typedef struct {
    int max[MAX_RESOURCES];
    int allocation[MAX_RESOURCES];
    int need[MAX_RESOURCES];
} Process;

int available[MAX_RESOURCES];
int num_processes;
int num_resources;

// 安全性检查
bool is_safe() {
    int work[MAX_RESOURCES];
    bool finish[MAX_PROCESSES];
    
    // 初始化
    for (int j = 0; j < num_resources; j++) {
        work[j] = available[j];
    }
    for (int i = 0; i < num_processes; i++) {
        finish[i] = false;
    }
    
    int count = 0;
    int safe_seq[MAX_PROCESSES];
    
    while (count < num_processes) {
        bool found = false;
        
        for (int i = 0; i < num_processes; i++) {
            if (!finish[i]) {
                // 检查Need[i] <= Work
                bool can_finish = true;
                for (int j = 0; j < num_resources; j++) {
                    if (processes[i].need[j] > work[j]) {
                        can_finish = false;
                        break;
                    }
                }
                
                if (can_finish) {
                    // 释放资源
                    for (int j = 0; j < num_resources; j++) {
                        work[j] += processes[i].allocation[j];
                    }
                    safe_seq[count++] = i;
                    finish[i] = true;
                    found = true;
                }
            }
        }
        
        if (!found) return false;  // 不安全
    }
    
    // 输出安全序列
    printf("安全序列: ");
    for (int i = 0; i < count; i++) {
        printf("P%d ", safe_seq[i]);
    }
    printf("\n");
    
    return true;
}

// 银行家算法主函数
bool banker(int process_id, int request[]) {
    // 1. 检查请求合法性
    for (int j = 0; j < num_resources; j++) {
        if (request[j] > processes[process_id].need[j]) {
            printf("错误：请求超过最大需求\n");
            return false;
        }
    }
    
    // 2. 检查可用资源
    for (int j = 0; j < num_resources; j++) {
        if (request[j] > available[j]) {
            printf("资源不足，等待\n");
            return false;
        }
    }
    
    // 3. 试探性分配
    for (int j = 0; j < num_resources; j++) {
        available[j] -= request[j];
        processes[process_id].allocation[j] += request[j];
        processes[process_id].need[j] -= request[j];
    }
    
    // 4. 安全性检查
    if (is_safe()) {
        return true;  // 安全，确认分配
    } else {
        // 不安全，回滚
        for (int j = 0; j < num_resources; j++) {
            available[j] += request[j];
            processes[process_id].allocation[j] -= request[j];
            processes[process_id].need[j] += request[j];
        }
        printf("不安全，拒绝分配\n");
        return false;
    }
}
```

## 五、死锁检测与恢复

### 5.1 死锁检测

**资源分配图简化法**：
1. 将进程-资源关系简化为矩阵
2. 使用类似银行家算法的简化过程
3. 如果最终所有进程都能完成，则无死锁

```c
// 死锁检测算法
bool detect_deadlock() {
    int work[MAX_RESOURCES] = available;
    bool finish[MAX_PROCESSES] = {false};
    
    // 标记已满足的进程
    for (int i = 0; i < num_processes; i++) {
        if (allocation[i]全为0) {
            finish[i] = true;
        }
    }
    
    bool changed = true;
    while (changed) {
        changed = false;
        for (int i = 0; i < num_processes; i++) {
            if (!finish[i] && request[i] <= work) {
                work += allocation[i];
                finish[i] = true;
                changed = true;
            }
        }
    }
    
    // 存在finish[i]=false的进程即为死锁进程
    for (int i = 0; i < num_processes; i++) {
        if (!finish[i]) {
            printf("P%d 处于死锁状态\n", i);
        }
    }
}
```

### 5.2 死锁恢复

| 方法 | 说明 | 代价 |
|------|------|------|
| **进程终止** | 终止所有死锁进程 | 高（重新执行） |
| **逐个终止** | 每次终止一个，检查是否解除 | 中（开销大） |
| **资源剥夺** | 从死锁进程剥夺资源 | 中（可能导致饥饿） |
| **进程回退** | 回退到之前的安全状态 | 高（需要检查点） |

**终止策略选择因素**：
- 进程优先级
- 已执行时间
- 已使用资源量
- 还需多少资源
- 进程交互类型（批处理/交互）
